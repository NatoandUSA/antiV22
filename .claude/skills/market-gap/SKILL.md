# Market Gap (internal)

## When to use
Before adding a feature, or when the user asks "what should we build next".

## Reference
`docs/MARKET_GAP_RESEARCH.md` — market tools reviewed, what we have, what we skip.

## Rules
- We are a **sales-execution + private-learning** system, not a research clone.
  Our edge: better offer, first image, personalization, supplier control, launch
  process, and private win/loss data — not public keyword parity.
- Adapt patterns (Cerebro→Spy reverse engine, Launchpad, Market Tracker, Profits,
  Alerts), never copy Amazon logic or any repo's code. Respect licenses.
- Every new feature must earn its place: does it help the team CHOOSE, BEAT, or
  LAUNCH better? If not, don't build it. Keep it simple for a non-technical team.

## Do NOT build
- Auto-publishing, Etsy account automation, ad execution, competitor scraping,
  or a feature that just duplicates eRank/EverBee research.

## Pass/fail
A proposed upgrade passes only if it maps to a real execution/learning gap and
does not clutter the dashboard or add a heavy dependency without clear payoff.

## What NOT to do
- Do not add features on spec. Prefer finishing/hardening what exists.
- Do not blindly copy code from GitHub; study patterns, implement cleanly.
